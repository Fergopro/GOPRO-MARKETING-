# Global AI homepage Preview

Branch: `goprocures-ai`. Production `main` must not be merged or deployed without owner approval.
Design: https://www.figma.com/design/EEJn3n6QX5hlMF9SvZ4Xpt?node-id=1-2

## Implemented

- Local Inter fonts and a pinned, vendored Supabase browser client remove homepage authentication/font CDN dependencies. Rebuild the client with `npm ci --prefix tools/vendor` then `npm run build --prefix tools/vendor`.
- Responsive blue/purple homepage with accessible voice/text tabs, mobile navigation, original orbital SVG exports, genuine approved Supabase testimonials, continuous scrolling with pause, keyboard/manual controls and reduced-motion support.
- Existing Gateway voice WebSocket integration retained. Actual microphone PCM and playback analyser drive waveform/orb intensity. Listening, processing and speaking states follow transport events and playback completion. Microphone mute and end controls stop/disable real capture.
- Shared account-scoped request persistence for text and voice, serialised writes, explicit customer confirmation, visible failures/retry and private attachment upload using the existing `client-documents` bucket and `request_files` table. No schema/policy changes.
- Existing procurement brain shared with text AI; progressive questions, exact specification matching, evidence levels and geographically appropriate sourcing. Original models retained. No automated supplier actions added.
- Text AI verifies the signed-in user server-side and rejects injected system roles/oversized conversations. Existing shared-page client also sends its user token.
- Conditional trial reservation prevents two concurrent start calls claiming one free trial. Existing entitlement checks, private server secrets and 60-second client cutoff retained.

## Preserved

Google/email sign-in, dashboard, requests, private documents, admin console, Pro management, quote entry/publication, client decisions, status tracking and existing database/security policies. All service URLs remain unchanged. Client attachments remain private; files are available to the procurement team, not automatically extracted by this text model.

## Verification

Run `npm test` for persistence ordering/retry, private attachment cleanup, text authentication/prompt injection and shared-brain regressions. Browser checks must cover 1440, 768, 390 and 320 widths, voice/text tabs and navigation, approved/empty reviews, signed-in request creation/confirmation, upload and surfaced failures, voice transport and trial/Pro gating.

Completed isolated browser checks: signed-in Text AI -> a single confirmed request -> private attachment -> existing customer dashboard -> admin attachment view -> admin quote entry/publication -> client approval. The real voice client also passed against isolated provider and microphone fixtures: transcript persistence, microphone mute, request confirmation and 60-second termination. All pages checked had no uncaught JavaScript errors. These fixtures never wrote to the live database. Desktop/tablet/390px/320px layout checks passed without horizontal overflow; all four approved orbital SVGs loaded at original dimensions.

Authenticated live checks require a real signed-in Free account, a used-trial account, a Pro account and an admin account. Automated fixtures do not establish successful production authentication or actual AI audio quality. Complete the live journey on Preview before any production approval.

Known inherited limitation: the direct browser-to-Gateway transport uses short-lived setup tokens, while the 60-second active-call cutoff is enforced by the client timer. Token expiry alone is not documented as a hard active-WebSocket session limit. An abuse-resistant billing/session termination layer and durable usage-event reconciliation are future server work; do not claim those are verified here.

## Future automation boundaries

Current stages: customer intake -> saved confirmed request -> protected administrator review -> manually sourced quotes -> admin publication -> customer approval/rejection and tracking.

Future workers should consume an immutable request snapshot and produce evidence-linked supplier research, then draft RFQs, parse quote attachments, normalise specifications/units/currency/Incoterms, and calculate landed costs. Keep research evidence and deviations separate from customer-visible recommendations. Use explicit states (draft, awaiting admin approval, approved, executing, completed, failed), idempotent job IDs, audit events and retries. Supplier emails, purchase orders, payments and logistics execution require protected admin approval; client confirmation is not that authority. Publish only reviewed comparisons. No worker, outbound email, supplier research tool, PO or logistics automation is implemented by this change.
